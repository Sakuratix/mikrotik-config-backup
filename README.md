# mikrotik-config-backup

Ночной экспорт конфигураций MikroTik в git. На выходе история изменений по каждому роутеру: кто, когда и что поменял в firewall, видно через `git log -p core-01.rsc`.

## Как работает

1. По SSH с ключом выполняется `/export show-sensitive=no terse`. RouterOS 6 этот флаг не знает и отвечает ошибкой синтаксиса: тогда скрипт повторяет с `hide-sensitive`, а не сохраняет ошибку вместо конфига.
2. Защита от утечки: если в выгрузке всё же есть `password=`, `secret=`, `private-key=`, PSK и т.п. со значением (не тот флаг, лишняя policy у пользователя), конфиг не пишется и не коммитится, роутер помечается как упавший, а в лог попадает только имя поля, без значения.
3. Строка с датой экспорта вырезается, иначе каждый прогон был бы изменением.
4. Роутеры опрашиваются параллельно, до `PARALLEL` (по умолчанию 8) одновременно: одна мёртвая площадка с SSH-таймаутом больше не задерживает всех остальных.
5. Коммит и push только если что-то поменялось. Код выхода 1, если хотя бы один роутер не ответил, чтобы cron или systemd это заметили.

## Установка

```bash
# на каждом роутере: setup-router.rsc (пользователь только на чтение, вход по ключу)
cp routers.example.txt routers.txt
git clone git@github.com:me/net-configs.git /srv/net-configs
BACKUP_REPO=/srv/net-configs ./backup.sh
```

Cron: `15 3 * * * BACKUP_REPO=/srv/net-configs /opt/mikrotik-config-backup/backup.sh`

## Тесты

`tests/test.sh` гоняет `backup.sh` без роутеров: на `PATH` подкладывается фейковый `ssh`, который отдаёт заготовленные экспорты RouterOS 6 и 7, а вместо GitHub используется локальный bare-репозиторий. Проверяется, что дата вырезается для обеих версий, CRLF убирается, при одинаковом конфиге нет коммита, а при недоступном роутере код выхода 1 и последний рабочий конфиг этого роутера не затирается.

## Зачем

Когда площадок десятки, фраза «вчера всё работало» без истории конфигов превращается в угадайку. С ней откат занимает минуту: `git show HEAD~1:club-msk-03.rsc`.
